# ASF Digital Platform

### A Digital Hub for Anglican Student Fellowship

## 1. The idea in one sentence

We want to create a **central digital platform for ASF** that brings together fellowship information, Bible study materials, FS, devotionals, the Bible, announcements, events, library resources, student resources, and other fellowship activities in one place.

Instead of ASF information being scattered across:

- WhatsApp
- Hard-copy manuals
- PDFs
- Physical books
- Different websites
- Personal phones
- Announcement groups

we create **one digital home for ASF.**

# 2. Why are we building it?

This is the first thing I would tell the President.

Right now, ASF already has a lot of useful resources and activities.

The problem isn't that ASF lacks resources.

The problem is **accessibility and organization.**

For example:

Someone wants to read Bible Study.

They need the physical manual.

Someone wants FS material.

They need the physical material or PDF.

Someone wants an announcement.

They have to find it in WhatsApp.

Someone wants a past question.

They have to ask somebody.

Someone wants a spiritual book.

They have to physically visit the library.

Someone needs help.

They may have to physically find the appropriate person.

The proposed platform brings these things together.

So instead of:

"Where can I find this?"

the member thinks:

**"Let me check the ASF app."**

That's the fundamental idea.

# 3. It is not just an app

This distinction is important when pitching.

We're proposing **one ASF digital platform**, with different interfaces.

### Public Website

For anyone.

It tells people:

- Who ASF is
- What ASF does
- Our programs
- Service times
- Location
- Leadership
- Contact information
- Giving information
- Gallery
- Other public information

Someone who doesn't belong to ASF can visit the website and understand what ASF is.

# 4. The Member Platform

Then there's the private member side.

This is where the real functionality happens.

A member can access things like:

**Home**

**Bible**

**Bible Study**

**FS**

**Hymn Book**

**Devotional**

**Library**

**Announcements**

**Events**

**Help Centre**

**Profile**

And eventually additional features.

# 5. How does someone access it?

We don't want this to feel like a school portal.

This is very important.

We're **not using matric numbers.**

ASF is a fellowship, not a department.

So authentication should be simple.

The direction we're leaning toward is:

### Phone-number authentication / Magic-link authentication

A member enters their contact details.

They verify it.

Then they can access the platform.

No complicated:

Matric Number + Password

No.

It should feel like joining a fellowship platform, not logging into FUTA's student portal.

This is where the app becomes interesting.

The first thing you see should be a **personalized dashboard**.

Something like:

**Good morning 👋**

### Today

📖 **Daily Devotional**  
Today's devotional

📚 **Bible Study**  
Today's/current Bible study

📢 **Announcement**  
Latest fellowship announcement

⏰ **Next Event**  
Bible Study - 5:00 PM

🎓 **Academic**  
Exam coming up in 8 days

Then perhaps:

**Continue Reading**

**Weekly Challenge**

**Upcoming Events**

So the application isn't just a storage box.

It becomes something members actually open.

# 7. Bible

The platform contains a Bible.

A member doesn't need to leave the platform to read the Bible.

For example:

Bible Study says:

**Text: James 2:14-26**

The user clicks it.

The application opens:

James 2:14-26

directly.

This makes Bible Study much smoother.

# 8. Bible Study

This is one of the core modules.

The entire Bible Study manual can be available digitally.

Instead of having:

Physical manual

the member can open:

**Bible Study**

and read the material.

It can contain:

- Topic
- Introduction
- Bible text
- Objectives
- Memory verse
- Discussion
- Questions
- Conclusion
- Prayer points

And Bible references are clickable.

So if the manual says:

Romans 8:28

the user can tap it and immediately read Romans 8:28 in the built-in Bible.

# 9. And importantly: previous Bible Studies remain available

This isn't necessarily:

"Today's Bible Study"

only.

The whole manual can exist inside the system.

So someone can say:

"I want to go back and read last month's study."

They simply find it.

This turns the platform into a **searchable archive of ASF's Bible Study materials.**

# 10. FS - Foundational School

FS will have its own controlled section.

Not everybody should see it.

The system knows:

FS Student

FS Teacher

FS Coordinator

Regular Member

and gives each person the appropriate access.

For example:

### FS Student

Can:

- Read lessons
- Access materials
- Complete assignments/quizzes if we decide to add them
- Track their progress

### FS Teacher

Can:

- Access assigned classes
- Upload materials
- Manage lessons
- Possibly monitor students

### FS Coordinator

Has broader FS permissions.

This is why **role-based access** is important.

# 11. Hymn Book

This is another existing fellowship resource that we want to digitize.

Instead of carrying the physical book everywhere:

Search:

"Humility"

or enter the:

Hymn number

and the platform finds it.

The idea is essentially:

**Physical fellowship resource → searchable digital resource.**

# 12. Daily Devotional

The devotional doesn't have to be uploaded manually every day.

This is an important part of the system.

The content can be prepared beforehand.

For example, administrators upload a year's worth of devotional content.

The system knows:

August 9 → Devotional A

August 10 → Devotional B

August 11 → Devotional C

and automatically displays the correct one each day.

So the Bible Study/Devotional team doesn't have to wake up every morning and upload something.

This is part of our goal:

**Make the system easy for future executives to operate.**

# 13. Announcements

This is another major feature.

Suppose the President wants to announce:

"There will be a general meeting immediately after service."

He doesn't need to call the technical team.

He doesn't need to touch the backend.

He opens an **Admin Dashboard** on his phone.

He clicks:

Create Announcement

Then:

**Title:** General Meeting

**Description:** There will be a general meeting immediately after service.

**Date:** August 9

**Time:** 6:00 PM

**Duration:** etc.

Then:

Publish

Done.

The members receive the announcement.

# 14. Different administrators get different permissions

This is important.

We're not going to have:

"One password that every executive shares."

Instead, everyone has their own account.

And their account has a **role**.

For example:

### President

High-level management permissions.

### Publicity Coordinator

Can manage announcements and publicity content.

### Bible Study Coordinator

Can manage Bible Study content.

### FS Coordinator

Can manage FS.

### Librarian

Can manage library resources.

### Technical Administrator

Can manage the actual system.

This means the technical team doesn't have to become the bottleneck.

# 15. What happens when executives change?

This is a very important problem we identified.

Imagine:

2026 President → leaves office.

2027 President → takes over.

We don't want the old President to still have access.

So we don't transfer passwords.

Instead:

**Old account:**

President → Removed

**New account:**

President → Assigned

The system changes the role.

The old executive still has their normal member account if appropriate, but they no longer have executive permissions.

This means the platform survives leadership transitions.

# 16. Library

This is another major part.

The library could contain:

### Spiritual Books

Books approved for digital access.

### Past Questions

For students.

### Fellowship Materials

Manuals and resources.

### Sermons/Media

Potentially later.

So a student can open:

Library → Past Questions → CSC → 300 Level

and find available materials.

Or:

Library → Spiritual Books

and read available books.

# 17. Important copyright consideration

One thing we'll have to handle properly:

We can't simply download copyrighted Christian books from the internet and redistribute them.

So the library needs a content policy.

We can use:

- Books ASF owns
- Materials ASF has permission to distribute
- Public-domain materials
- Properly licensed digital books
- Links to legitimate external sources

# 18. Help & Suggestion Box

This is one of the features that can make a real difference.

Imagine a member needs help.

Instead of asking:

"Who do I talk to?"

They open:

**Help Centre**

Then:

I need help.

They select something like:

- Prayer request
- Welfare
- Counseling
- Academic
- Fellowship issue
- Suggestion
- Other

They submit it.

The appropriate person receives it.

This can be private.

It removes the friction of physically finding the right person.

# 19. Events

The platform should know about ASF events.

For example:

**Sunday Service**

Tomorrow - 8:00 AM

**Bible Study**

Tuesday - 5:00 PM

**Vigil**

Friday - 10:00 PM

The system can remind members.

For example:

🔔 Bible Study starts in 30 minutes.

The purpose isn't complicated attendance tracking.

The goal is simply:

**Don't let members miss important fellowship activities.**

# 20. Offline-first

This is one of the strongest technical/product decisions.

We don't want the application to depend entirely on internet access.

Resources such as:

- Bible
- Bible Study
- FS materials
- Hymn Book
- Downloaded books
- Previously viewed content

should be available offline where technically/licensing-wise possible.

So during a service:

Someone can open the app.

No data.

No problem.

They can still read the Bible.

They can still open Bible Study.

They can still access downloaded resources.

Then when internet comes back, the app synchronizes.

# 21. Weekly Challenges

This could be something like:

### This Week's Challenge

Read the Gospel of John chapters 1-5.

Or:

Memorize Romans 12:2.

Or:

Spend 15 minutes in prayer each day.

The member can mark it complete.

It gives people a reason to come back.

Remember:

**ASF is a student fellowship.**

So the platform should also help students academically.

Potential features:

- Past questions
- GPA calculator
- CGPA calculator
- Study resources
- Academic announcements
- Exam countdown
- Study planner

Not necessarily all of these in version one.

But the philosophy is:

**Help the member spiritually AND as a student.**

# 23. Photo Calendar

Imagine a calendar:

**August 2026**

And different days have photos from ASF activities.

For example:

August 2 → Sunday Service

August 5 → Bible Study

August 8 → Fellowship Program

Over time, ASF builds a **digital history of its activities.**

That's actually valuable.

Someone years later could look back and see:

"This was ASF in 2026."

# 24. Member Directory

Potentially:

- Name
- Department
- Level
- Unit
- Contact information, where appropriate

But privacy needs to be handled carefully.

We don't necessarily want everybody seeing everyone's phone number.

# 25. The "nearest ASF member" idea

Technically, something like this is possible.

But we won't make **live location sharing** part of the first version.

Instead, if we ever implement the concept, it should be strictly **opt-in**.

For example:

"I'm available to connect."

Then members nearby could potentially discover one another.

But nobody's location should automatically be exposed.

# 29. The philosophy behind the platform

### 1. Simple
A normal student should understand it immediately.

### 2. Offline-first
Important resources shouldn't disappear because the network is bad.

### 3. Low-maintenance
Executives shouldn't need developers to perform normal activities.

### 4. Secure
Members' information and private requests must be protected.

### 5. Sustainable
The platform shouldn't collapse when the current executives graduate.
